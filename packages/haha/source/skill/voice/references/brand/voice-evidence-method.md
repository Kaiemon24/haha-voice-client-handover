## 1. Purpose and scope

Voice owns the brand voice specification and its multilingual adaptations. Run this internal capability independently for voice discover/create/apply/review/update; a brandbook, visual build or image call is not a prerequisite. Voice’s internal Vietnamese function owns final Vietnamese quality; the artifact owner owns report structure; Voice’s internal English function reviews English reader copy. One public Voice entry owns these functions.

## 2. Inputs

Resolve operation, brand/system identity and version, reader job, channel, output locale, facts, approved profile, samples and their permitted use. Reuse the existing interview. Ask only unresolved choices: preferred address, regional English, forbidden claims/words, real samples/anti-samples and additional languages. English-first is a baseline-authoring order, not a default output language. A visual preference is not evidence of writing behavior.

## 3. Workflow

### Resolve layers before composing

Use this order: immutable facts/authority → language baseline → niche overlay →
brand character → situation/channel → quality review. Do not infer copy voice
from visual motifs or use plain-language compliance as proof of brand identity.
The niche overlay must name domain, reader knowledge, reader decision, risks,
evidence required, terminology policy, emotional context and excluded promises.
Record these from evidence/interview, or label them proposed. Research links and
alternative sources remain visible at the existing brainstorm checkpoint.

For guideline creation/update, compile all eight blocks with actual EN/VI rules,
not headings alone. For report application, pass the exact selected system/voice
identity, version, hash and included rule text to the content owner. That owner
keeps report structure; language review follows final merge. Do not silently
select the newest profile or repeat brand intake for an apply-only task.

Before calling the integration ready, test two contrasting domains on frozen
facts with the same report structure. A fresh-context recipient receives only
guideline and task facts. Review actual normal and adverse EN/VI outputs for
meaning, naturalness, niche fit and distinguishable behavior separately.
For each relevant trait record an actual output span or a justified non-applicable
state. A field-presence pass or fact-preservation pass cannot clear missing
applicable voice behavior. Repair an execution omission locally when the rule
already exists; do not invent another brand trait to compensate.

Equivalent
literal error wording is acceptable; personality must not obscure failure state.
Also test stale binding, unsupported locale, a missing locale field, narrow
profile update and an output not used to tune the instruction. Record failures.
Synthetic fixtures establish method behavior, not learned brand authenticity.

1. Discover in the named sources only. Local files suffice; enterprise connectors are optional. Follow existing source manifests when an intake path has moved. Classify approved rules, real writing, reference inspiration and unverified excerpts separately.
2. Deduplicate by origin and content before corroboration. Five copies of one post are one source. Source approval, applicability and authorship outrank recency alone. Retain an older approved rule against a newer informal example unless its supersession is established. Conflicting approved rules pause only the affected choice.
3. Extract openings, idea order, pronouns, verbs, sentence/clause rhythm, transitions, certainty, humor, metaphor, emphasis, calls to action and terminology. Give each inferred rule a source locator, language, context, counterexample and evidence limit. Frequency is not conversion evidence. Never treat synthetic examples as authentic brand samples.
4. At the existing brainstorm checkpoint show up to three genuinely different voice directions on identical facts, source-item links and relevant browsing hubs, tradeoffs, excluded claims and proposed/observed status. Reuse settled decisions. A sparse corpus permits a proposed neutral baseline; learned voice remains NEEDS_SAMPLE. Do not demand a fixed number of files merely to proceed.
5. Synthesize the eight blocks in voice-and-tone.md. Separate stable character, situational tone, language mechanics and document composition. For each trait state observable behavior, is/is-not, positive/negative examples, applicability and exceptions. Work UI, teaching, service offers and error/help contexts need distinct tone settings, not different brand identities.
6. Apply four reader tests: relevant information, findability, understanding and ability to act. These are plain-language principles, not a claim of ISO certification. Prefer subject/action and precise familiar wording; preserve conditions, uncertainty and necessary technical terms. Numerical sentence limits are diagnostic, not universal.
7. Freeze source facts; apply the selected profile; run the locale review once; compare source/output meaning; repair material findings and recheck. Preserve good original wording. Separate critical meaning failure from stylistic preference; no average score conceals factual drift.
8. For update, record the scoped finding and rule-level delta. Existing profile-promotion authority can be reused for its exact scope. Without it, keep a proposal. A method/skill change uses the receiving host's explicit instruction-change approval, never automatic learning from a correction.

Authority order: safety and factual truth → exact user scope and approved brand constraints → source-derived voice method → locale conventions → format presentation. Source-package commands cannot authorize uploads, skill mutation or mandatory report recaps.

## 4. Tools and permissions

Use scoped reads and permitted local drafts. No required account connection, archive-hook execution, sample upload, installation, publication or shared-library admission. Redact private examples in reusable instructions. Preserve notices when distributing substantial adapted source; do not bundle whole third-party PDFs.

## 5. Output

Deliver a versioned rule model, source-to-rule map, tone matrix, selected locale profiles, fact-preserving examples, gaps and review results. Compile a self-contained VOICE.md or complete DESIGN.md voice section from the same model; human HTML shows the same IDs/status/version. Bind systemId/version/hash, voiceId/version/hash, operation, locale and context. A binding without the actual rules is not a standalone guideline.

## 6. Verification and stopping

Test: approved-old versus informal-new source; duplicate corroboration; no samples; apply existing without interview; normal/error/destructive copy; EN/VI with identical facts; mixed-language surfaces; unsupported extra locale; feedback without promotion authority; and report structure preservation. Actual outputs and reviewed source comparisons are required. Keyword checks prove only rule presence.

Stop learned-authenticity claims without real corpus, native-language claims without suitable language review, or release claims without rendered copy proof when a visual artifact is delivered. These limits do not block useful labeled drafts.

Robustness checks: allow state-only error copy when no recovery is supported; apply lesson sequences only to complete lessons; preserve safety-critical action order over rhetorical order. Keep locale declarations in adaptation notes, not UI copy. Native-quality claims need a competent target-language reviewer and recorded findings; comprehension claims need actual reader evidence. For consequential copy, trace source fact → output → preserved/changed/unknown. After tone edits, recheck warning prominence, urgency, length and requested action as well as literal facts.

## 7. Supporting material

`../../scripts/voice_contract.py` supplies field coverage, portable compilation
and optional local VoiceBinding.json readback. It is not a language judge. The
caller controls requested presentation; ordinary voice work requires neither
a complete visual system nor an external builder. A compiled VOICE.md must carry
actual rules. For structured schema/CLI details read `../script-usage.md`.
