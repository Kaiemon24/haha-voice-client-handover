## 1. Purpose and scope
Compile the brand's writing contract so a receiving agent can write without
the originating OS, skill installation, hidden context or internal paths.
The guideline is a versioned output from Voice, not a new instruction owner.

## 2. Inputs
Both default EN and VI baselines (or an explicit task-scoped exception), approved/provisional voice rules, source/corpus
records, situations, real component behavior, claims and terminology.
Include applicable language-review rules, distinct writing/speaking audiences
and settings, explicit user preferences and their scope. Separate approved
brand facts, observed samples, proposed interpretation and unresolved facts;
never derive voice from a donor identity, palette or brand name alone.

## 3. Workflow
Include all eight parent blocks directly: context, observable traits, tone
matrix, language mechanics, claim guardrails, component copy, examples and
governance. Preserve stable rule IDs, status, appliesWhen, exception,
sourceRefs, confidence, positiveExample and negativeExample.
For each language give actual writing instructions, address choices,
terminology, rhythm guidance, opening/ending choices and original examples.
For languages beyond EN/VI, include the actual locale conventions and review
limits; a list of language names is not an adaptation. English-first authoring
must not force English output. An optional VOICE.md must include the complete
selected rules and procedure, not only a link to DESIGN.md or an OS skill.
For each situation show information order, allowable personality, forbidden
implications and next-action pattern. Include unknown/error/destructive states
only where applicable; never invent saved data, safe retries or free offers.

Provide a complete writing procedure: read facts; list immutable fields; choose
language/channel/tone; draft; compare meaning; inspect naturalness; return
unknowns rather than fill them. Explain unfamiliar terms inside the guideline.
Include source links for independent choice but never make them necessary for
basic execution. Do not refer to "use our skill" as a substitute for a rule.

### Complete language and brand compilation

Compile the actual selected baseline and applicable language-review instructions
into each delivered brand guideline, covering both EN and VI by default. A link,
eight headings, language names, or a short generic summary is not the closure.
Preserve each load-bearing instruction and its scope; authoring may resolve
shared Voice modules, but receiving execution requires only delivered text and
frozen task facts. Do not copy private samples or entire third-party guides.

For EN, include concrete subjects/actions, familiar precise words, stable terms,
appropriate active/passive voice, expanded unfamiliar acronyms, consistent
address and coherent parallel lists. Adapt rhythm to genre without a universal
sentence limit; avoid patronizing wording and unsupported promotion. Review
repetition, vague abstractions, inflated claims, formulaic transitions and
unnecessary jargon while retaining approved voice, valid uncertainty and facts.

For VI, include meaning-first Vietnamese idea order; explicit address without
inferred age/gender/intimacy; concrete verbs; audience-fit Hán Việt, regional
and borrowed terms; natural clause/paragraph rhythm and read-aloud review.
Use natural Vietnamese when precise. Keep necessary English technical terms
only for an operational reason, explain their concrete job at first use in
each standalone section, preferably within five and at most nine Vietnamese
whitespace-counted words; rewrite or add a note if that would distort meaning.
Preserve exact product labels, accents, actors, negation, permission conditions,
uncertainty and audience-specific date/number/unit conventions. Word counts
measure layout, never impose translated English sentence limits.

For both languages, compare actors, actions, objects, quantities, units, dates,
conditions, causality, certainty, rights and obligations with frozen inputs.
Assess meaning and naturalness separately; a fluent sentence cannot excuse
changed facts. Apply the appropriate review to each mixed-language unit and
preserve machine keys and locked source labels. Keep internal production
narration out of reader copy unless it changes the reader's decision. Include
original positive/negative examples and normal/error/unknown situations where
applicable; mark missing authentic language samples provisional.

Adapt all eight blocks to source-grounded brand behavior. Each trait or example
must name its observable effect, applicable situation and evidence/status;
generic adjectives are insufficient. Approved target guidance and explicit
current preferences control their scope; inspiration cannot establish target
claims or overwrite approved wording. Missing facts require a targeted question
or a labeled proposal, never an invented authentic brand personality.

### Writing and speaking

Carry separate applicable instructions and EN/VI examples for written copy and
spoken explanation within the same rule model. Writing covers scan order,
headings, paragraphs, labels and exact states. Speaking covers information
order, one idea per beat, natural sentences, pauses and how to explain an
unfamiliar term; it is wording guidance, not audio synthesis or timing authority.
For a user preference to explain work to an implementation team step by step,
use short clear steps, name each action and its purpose, explain necessary
terms and give the immediate check/next action. Preserve dependency, permission
and uncertainty rather than shortening them away. Keep that preference scoped
to the named speaking situation unless broader application is authorized.

Maintain one source rule model. VOICE.md is its complete focused textual
projection; any requested HTML/document presentation shows the same core
rules/status/version. Use the `brand-voice/v1` field model and
`../../scripts/voice_contract.py` for optional machine-checkable field coverage.
Read `../script-usage.md` for schema and CLI guidance. Field completeness does
not prove naturalness, observed brand authenticity or visual release. Verify
eight complete framework blocks, written/spoken distinction, both language
baselines and applicable review rules in the delivered guideline. The receiving
client needs only that guideline and task facts to write; source scripts, a
Design skill and the originating workspace are not execution prerequisites.

## 4. Tools and permissions
Receiving agent needs only the delivered text and task facts for writing.
Web research, external send, installation and canonical rule changes are not
implicitly required or authorized. Exclude private corpus unless handoff is
explicitly authorized; paraphrased rules can be delivered without raw samples.

## 5. Output
Self-contained brand guideline in VOICE.md or the requested complete format;
rule/version/hash binding; safe sample references; missing-information list.
Label an uncalibrated profile proposed, never the user's established voice.

## 6. Verification and stopping
Give a fresh reader/agent only this delivered guideline and frozen task facts.
Test a normal text, a constrained UI message and an adverse/uncertain case,
covering both EN and VI by default for guideline creation/update; record an
explicit scoped exception if requested. Compare exact facts, conditions,
quantities, negation, address and actions with inputs. Record actual outputs,
not only expected answers. Use a held-out sample when real corpus is available.
Verify no required internal skill/path/link is missing and parity between any requested human and agent formats.
Blocked external sources must not prevent using the already included baseline.
Do not claim authentic brand fit from synthetic tests alone.
Include a written-versus-spoken pair on the same facts, an implementation-team
explanation when selected, a missing brand fact and a negative package that
contains only headings or an internal Voice link. Test from the delivered
closure with source OS paths unavailable; reject incomplete compilation and
unsupported authenticity claims. Same-agent examples prove only those reviewed
examples; fresh-context, native/rendered and human calibration evidence remain
separate and explicitly pending when absent.

## 7. Supporting material
voice-and-tone.md owns the eight-block module; voice-baselines.md supplies
language modes at authoring time. These dependencies must be compiled into the
delivered guideline, not demanded from the receiving agent.
