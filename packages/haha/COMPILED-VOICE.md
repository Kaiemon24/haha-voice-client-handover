# Voice

## 1. Purpose and scope

One functional owner for writing voice, situational tone, multilingual guideline
research, application, and final EN/VI language review. The selected approved brand profile controls character and register;
Vietnamese and English reviewers are internal functions, not competing profile
owners. The caller retains facts, strategy, structure, rendering and export
permissions. No Design skill, global OS kernel, project layout or private path
is a runtime prerequisite.
Do not route audio synthesis, voiceover timing or machine-only fields here.

## 2. Inputs

Resolve requested operation, reader job, language/locale, surface and states,
immutable facts, approved wording, selected system and actual voice rules with
version/hash. Reuse existing scope and choices. Missing facts or conflicting
approved rules block only affected copy; no invented brand or renewed intake
for baseline/apply-only work. Samples remain task data, not reusable private rules.

## 3. Workflow

Read `references/output-voice.md` before drafting and after final merge.
Select one profile, then only required internal functions:

| Need | Read | Selection rule |
|---|---|---|
| Apply/default/review copy | `references/output-voice.md` and `references/output-handoff.md` | Selected approved system voice wins; use actual task language. |
| Baseline or missing language mechanics | `references/brand/voice-baselines.md` | Neutral baseline never proves learned brand identity. |
| Discover/create/learn/adapt/update a profile | `references/brand/voice-and-tone.md`, then its named evidence/portable modules | Preserve original eight blocks, source method and existing checkpoints. |
| Vietnamese writing, translation or final review | `functions/vi/README.md` and triggered local references | Meaning-first workflow; final-merge PASS/WARNING/BLOCKED and actual source comparison. |
| English final review | `functions/en/README.md` and selected catalogue | Lint, preserve meaning/voice, repair, re-lint; no English catalogue on Vietnamese. |
| Compile/check a brand guideline/binding | `scripts/voice_contract.py` | Stable brand-voice/v1 interfaces; field checks are not writing-quality proof. |

Order: resolve controlling rules → freeze facts and protected machine values →
draft with content owner → final merged copy inventory → per-language review →
native/rendered state readback → return copy and bound receipt to caller.

## 6. Verification and stopping

Its hash/coverage checks supplement semantic and native/rendered review; it is
not an automatic OS-wide interceptor or a naturalness/authenticity certificate.

selected/partial/stale profiles, mixed languages, protected machine values and
later merge invalidation. Missing required review/tools blocks readiness for

## Receipt and invalidation

Before handoff, keep a task-owned `voice-output-review/v1` JSON receipt:

- `phase`: `final-merge`; `owner`: caller; `voiceOwner`: `voice`.
- `rules`: nonempty file refs `{path, sha256}`, plus identity/version and selected

- `copy`: file ref to JSON `{units: [{id, language, state, text}]}` containing

- `coverage`: file ref to a consumer-extracted native/rendered readback JSON
  with the same units and states. For text-only deliverables, actual output
  readback is sufficient; visual/interactive outputs also need rendered evidence.
- `artifact`: file ref to the exact delivered output or local native-revision
  readback envelope; envelope must identify the real destination/revision.
- `states`: exhaustive required state IDs from the actual artifact inventory.
- `reviews`: one row per unit, `{unitId, textSha256, verdict, reviewer, evidence}`.
  `verdict` is PASS only after actual source/meaning, selected-voice and language
  comparison. Evidence is a hash-bound written comparison of source/output spans
  and voice traits, not a self-declared boolean. EN/VI lint results stay attached.
- `renderEvidence`: hash-bound observations/screenshots for visual states, each
  `{state, evidence}`; `requiresRender` is true for visual/interactive output.
- `openBlockers`: empty only when no critical/major unresolved issue remains.

Run `scripts/verify_output_receipt.py RECEIPT`. Missing, duplicated, changed or
unreviewed units/rules/states/evidence fail. Native/rendered extraction and review
must be real and inspected: this script verifies identity/coverage, not whether a
human review is truthful, a sentence means the same thing or an inventory is
exhaustive. It never calls a model, writes production output or grants export.

state coverage or artifact revision invalidates affected receipts. Re-extract,
review and render affected content before handoff; never reuse a prior PASS from

## 1. Purpose and scope
Supply English and Vietnamese guideline baselines by default for every brand
inside Voice, not only KAI. Baselines
improve intelligibility and consistency; sample-derived brand voice and
situation-specific tone are separate layers. Brand samples cannot override
facts, rights, permissions or content-owner decisions.

## 2. Inputs
Language/locale, audience, channel, reading job, approved facts and terminology,
existing voice profile, selected samples/anti-samples and rights. Missing EN
samples do not become independent evidence by translating VI samples.

## 3. Workflow
### Default guideline coverage
For create, setup, complete, adapt or update of a brand-voice guideline, include
both EN and VI without asking the user to select between them. On update,
preserve approved rules and fill the missing language or affected rule gaps;
do not rewrite already-good content. Only an explicit task-specific language
restriction narrows this default; record that exception. Additional languages
extend rather than silently replace EN/VI.

For each language include concrete writing rules, address/register, terminology,
tone by situation, original do/don't examples and normal/error/uncertain copy
where relevant. Review each language naturally, then compare shared facts,
conditions, quantities and certainty. Vietnamese is not a literal English
translation; parallel meaning does not require identical syntax or length.
Missing authentic samples in one language yields a proposed baseline for that
language, not fabricated evidence or a blocked neutral draft.

This default concerns the guideline, not every generated product. For apply-only
copy, use the task's requested language and do not translate the whole system,
repeat intake or update a pinned profile merely to apply it.

### EN
Prefer concrete subjects/actions and familiar precise vocabulary. Use active
voice when responsibility matters; passive voice is valid when the actor is
irrelevant or unknown. Keep terms stable, expand unfamiliar acronyms, and make
parallel lists coherent. Choose person/address from the relationship.
Adapt rhythm to genre; do not impose one numerical sentence limit. Explain
without patronizing ("obviously", "just", "easy") or unsupported promotional
claims. Preserve negation, qualifiers, dates, units and conditions.

Google's technical voice guide informs approachable, respectful explanation.
Apple's international/inclusive editorial sections inform clarity and context.
These sources do not prescribe every brand's personality. ASD-STE100 is
optional technical-domain research; if the applicable standard is inaccessible,
record that fact and do not claim conformance or import unverified rule counts.

### VI
Write from intended meaning and natural Vietnamese idea order, not a translated
English skeleton. Decide address explicitly; "bạn", "anh/chị", "quý khách",
"mình", "chúng tôi" and "chúng ta" differ in relationship and responsibility.
Do not infer age/gender/intimacy. Omit a pronoun only when its referent is clear.

Prefer concrete verbs over unnecessarily nominalized phrasing. Hán Việt,
regional wording and borrowed terms are allowed when they convey precise
meaning for this audience; never apply a blanket purism rule. Explain unfamiliar
terms at first use and preserve exact product labels. A user's intentional
register outranks generic preferences, not factual fidelity.

Inspect clause/paragraph rhythm and read aloud.
For an unfamiliar technical noun, explain its role in the reader's decision
instead of preserving a literal calque. Keep an approved audience glossary when
one exists. Do not invent the measurement method, time period or numerical
reference merely to explain a term. Remove a repeated prerequisite only when
its actor, condition and certainty remain explicit once in the delivered copy.

Whitespace-token counts are
layout measurements, not a linguistic word-count standard or translated EN
sentence threshold. Date/decimal/currency conventions follow the chosen
audience and brief, not an unannounced global default. Preserve accents,
negation, actor, approval condition and uncertainty ("có thể", "dự kiến").

### Learn and calibrate
Before learning, classify approved guidance, real samples and inspiration
separately; deduplicate origins. Approval and applicability outrank recency
alone. A neutral proposed baseline is not a learned authentic brand voice.
Start with roughly five user-approved diverse pieces and 1–2 anti-samples when
available; the PDF quantity is a practical suggestion, not statistical proof.
Record source ID/locator, language, author/date/channel, approval and privacy.
Extract openings, address, rhythm, vocabulary, transitions, endings and tone.
Each observation needs cited samples, counterexamples and confidence. One
slogan is not a universal rule. Distinguish preferred/allowed/avoid/prohibited
terms with reason, scope, replacement and exceptions.

When evidence is insufficient, offer up to three original direction examples
with the same facts and linked source alternatives. A selected source may
inform mechanics without supplying brand identity. Retain one suitable sample
for held-out review where available; otherwise label authenticity untested.

### Additional locales

Declare language-region tag, script/direction, forms of address, punctuation,
date/number/unit conventions, terminology, segmentation and font/glyph needs.
Learn from target-language examples rather than treating a translated English
sample as independent evidence. Preserve one brand character while realizing
it naturally in each language. Right-to-left and CJK layouts require their
own reading-order, shaping and line-break checks. Without sufficient samples
or a competent review, label the profile provisional; do not promise native
quality or claim every language is supported.

- **Generic vocabulary:** Translate operating and marketing shorthand by
  meaning. Familiarity inside the team does not justify English.
- **Proper identity:** Preserve exact brand, product, company, person, platform,
  publication, event, official campaign, legal title, and registered feature
  names when translation would damage identity.
- **Machine layer:** Preserve URLs, paths, filenames, stable IDs, schema keys,
  HTML classes, data attributes, commands, code, formulas, configuration values,
  color codes, units, and authoritative standard codes.
- **Bounded override:** Allow mixed-language prose only when the user explicitly
  requests it for one artifact. Do not turn that exception into a new default.


## 3. Workflow

### WORKFLOW

**Cross-skill handoff:** When another skill owns the report, slide, deck,
document, dashboard, interface, or design artifact, that skill keeps facts,
source structure, visual layout, and export mechanics. Activate this owner on
the final merged reader-copy layer, before layout or export, and return the
repaired copy plus its QA receipt to the parent skill. This handoff is
mandatory for reader-facing Vietnamese even when the parent skill did not
explicitly request a language review. Do not change layout, numbers, sources,
object structure, or strategic intent while applying this gate.

For machine-shaped prose, register-sensitive editing, or English-to-Vietnamese structural cleanup, read [Vietnamese humanization, register, and translationese](references/humanization-register-and-translationese.md). It adds three-layer diagnosis, intervention levels, false-positive controls, and a two-way audit without creating another voice owner. For final merged report or slide text, also read [Vietnamese lint–rewrite–re-lint gate](references/vietnamese-lint-rewrite-gate.md) and [Nhận diện văn tiếng Việt có dấu hiệu máy móc](references/vietnamese-ai-sounding-detection.md); run `scripts/check_vietnamese_release.py` before and after repair. Use PASS/WARNING/BLOCKED, never a single naturalness score.

1. **State the reader job:** Name what the reader must understand, decide,
   approve, feel, or do.
2. **Lock source truth:** Record actors, objects, ownership, time, location,
   causality, comparison, direction, conditions, uncertainty, quantities,
   permissions, and limits.
3. **Resolve ambiguity:** Mark a source term when competing meanings would
   change the decision. Ask or preserve the exact term with an explanation;
   never hide ambiguity behind fluent Vietnamese.
4. **Rebuild from meaning:** Draft without following English word order. Put
   the decision-relevant point where a Vietnamese professional expects it.
5. **Adapt the document:** Use the register of a report, marketing argument,
   technical instruction, brand passage, presentation, or internal note.
6. **Handle terminology:** Apply the technical-term exception before polishing
   rhythm.
7. **Edit with restraint:** Keep already-natural wording. Remove only patterns
   that harm clarity, register, rhythm, specificity, or trust.
8. **Read without the source:** Check first-read clarity, natural rhythm,
   concrete wording, causal flow, and speakability.
9. **Reopen the source:** Recheck every changed sentence. Preserve meaning,
   factual limits, and the reader's resulting decision.
10. **Inspect the assembled reader layer:** For HTML, apps, tabs, accordions,
    templates, and JavaScript-generated sections, run the language scan only
    after the final data merge and DOM assembly. Open every reader-visible state;
    source-file prose alone is not release evidence.
11. **Explain the signal before repairing:** Classify each finding as a lexical,
    structural, source-bound, or merge-layer signal; record the line, source
    claim, repair, and limit. A signal opens review, not an automatic rewrite.
12. **Release or block:** Run the deterministic final-merge lint after the
    last data assembly. BLOCKED findings stop release; WARNING findings require
    wording review; PASS still needs source, reader, and rendered checks.
    Block critical or major drift, repair minor voice defects, and repeat the
    source regression check.

For a glance-first Vietnamese report scene, preserve the underlying claim while
rewriting each visible unit for its own reading job. Prefer one concrete lead
phrase and one short explanation per card. Do not preserve an English-shaped
paragraph merely by distributing its sentences across decorative cards. Treat
machine-layer English and user-approved proper tab names as exceptions, not as
permission for generic English labels in the rendered body.

When a Vietnamese report adapts a foreign-language or mixed-language reference,
match the reference's content job, evidence depth, and reading mechanism—not its
functional vocabulary. Translate headings, navigation, labels, captions,
status, calls to action, timeline names, and explanatory jargon into natural
Vietnamese after the final data merge. Preserve only verified brand names,
legal names, URLs, official source titles, and a necessary specialist term that
passes the exception below. A reference-parity score cannot waive this reader-
layer language gate.

For a client pitch deck modeled on a research-heavy reference, borrow its
selection logic rather than its wording: state the useful fact or insight, add
the business implication only when it changes the decision, then name the
proposal or next step. Move methodological caveats, source qualifications and
analyst self-commentary to the linked proof layer unless they materially change
the slide's conclusion. An identity slide remains factual; a recommendation
slide remains decisive. Split multi-function prose into two or three short,
parallel Vietnamese bullets and preserve a presentation-sized body role instead
of shrinking text. Reject prose that sounds like a verifier speaking to another
agent when the audience is the client.

### TECHNICAL-TERM EXCEPTION

Keep an English technical term only when every condition passes:

1. **Necessity:** Vietnamese alone would reduce operational precision, make
   lookup or interface matching harder, or create a misleading substitute.
2. **Operational need:** The exact English form is needed for implementation,
   documentation cross-reference, interface matching, or specialist work.
3. **First use:** Write `English term (Vietnamese explanation)` at the first
   reader-facing use in each standalone section.
4. **Length:** Use 1–9 Vietnamese words, counted by whitespace after Unicode
   NFC normalization.
5. **Adaptive brevity:** Prefer five words or fewer. Use words six through nine
   only when they remove a real ambiguity or prevent a wrong action.
6. **Child-simple meaning:** Explain the concrete job or effect in plain
   language. Do not repeat the term, introduce another unexplained abbreviation,
   or add a new factual claim.
7. **Accuracy fallback:** If nine words cannot explain the term accurately,
   rewrite the sentence, add a short glossary note, or block the output. Never
   compress until the meaning becomes false.
8. **Restraint:** After the first explanation, let the English term stand alone
   in the same bounded section. Explain it again only when a later section can
   be read independently.

Reject English when natural Vietnamese is already precise, including generic
words such as `workflow`, `brief`, `research`, `draft`, `status`, `scope`,
`approval`, `output`, `input`, `handoff`, and `QA` in ordinary prose.

### DOCUMENT PROFILES

- **Report:** Lead with the conclusion or recommendation. Preserve uncertainty
  and separate evidence, interpretation, implication, and action.
- **Marketing:** Keep the human tension and action concrete. Do not invent
  intensity, benefit, urgency, or persuasion.
- **Technical:** Preserve object identity, sequence, conditions, permissions,
  failure states, and recovery boundaries before optimizing fluency.
- **Brand:** Preserve emotional precision and recognizable intent without
  inflating warmth, confidence, or distinctiveness.
- **Presentation:** Use one speakable decision unit per beat and preserve the
  logical relationship between beats.

### ERROR MODEL

- **Critical:** Reject a changed decision, causal path, condition, permission,
  technical object, safety boundary, or factual limit.
- **Major:** Reject a dropped or broadened fact, qualifier, responsibility,
  direction, certainty, antecedent, identity, or professional role.
- **Minor:** Repair wording that sounds translated, abstract, repetitive,
  stiff, bureaucratic, or tonally uneven while preserving truth.
- **Note:** Record an optional improvement that does not justify another edit.

Critical or major errors make the output ineligible regardless of fluency.

### RELEASE CHECK

Confirm all of the following before handoff:

- **Vietnamese origin:** The sentence could plausibly have been written directly
  in Vietnamese.
- **Read aloud:** It sounds natural on one normal-speed reading.
- **Meaning:** A non-specialist can paraphrase it correctly.
- **Specificity:** It names the behavior, evidence, object, or decision.
- **Causality:** Every connector represents a real logical relationship.
- **Terminology:** Every remaining English term is necessary, explained, and
  within the nine-word cap.
- **Reader layer:** Machine keys remain hidden from readers without breaking
  the underlying artifact.
- **Regression:** Source truth remains unchanged after the Vietnamese-only edit.

# Five principles

The rewrite half of the system. De-slopping removes what is wrong; these decide what the
line should say instead. Each one carries a real before/after from the Ridgeline Roofing
build (historical upstream examples; that example file is not bundled here).

## 1 · Don't make me think
*Steve Krug, "Don't Make Me Think", 2000.*
The reader decides in seconds whether this page is for them. Every line they have to
decode is a line they skip.

> **Before:** Premium materials that hold against the years
> **After:** A roof is seven layers. Most quotes only price two.

## 2 · Name the pain first
*Daniel Priestley's pitch order: open on the problem and the insight, not the product.
Alex Hormozi makes the same argument from the offer side — the reader buys relief from a
named problem, not a product description.*
Nobody buys a solution to a problem they haven't admitted. Every customer also has a
specific fear; naming it is worth more than any reassurance, because reassurance is what
the people who burned them also offered.

> **Before:** Get a free, no-obligation quote today
> **After:** You get a written scope and a fixed number before anyone climbs a ladder.

## 3 · Specific or silent
A vague benefit is worse than no benefit. Credibility comes from claiming something
checkable, not from claiming more. The more precise the claim, the less it needs a
superlative propping it up. And a refusal positions better than a promise — anyone can
promise quality, almost nobody publishes the work they turn down.

> **Before:** Committed to the highest standards of workmanship
> **After:** We do not do overlays. If the roof needs replacing, it gets stripped.

## 4 · One ask per screen
Two CTAs is zero CTAs. One action per screen, and the button says what it does —
"Book a free inspection", not "Get started".

> **Before:** Button
> **After:** Book a free inspection

## 5 · Under five minutes
The whole page should read in less time than the product takes to try. Teach something on
the way past: a page that explains how the thing works earns trust that a page of claims
cannot buy, and it arms the reader to spot a bad competitor — a favour they remember.

> **Before:** We use only the best underlayment available
> **After:** Full coverage, not the 15lb felt strip that shows up on cheap quotes.

## The rule above all five

**Never invent proof.** No customer counts, no testimonials, no ratings the business has
not earned. Where a build needs a proof slot it does not have, say so on the page:

> **Before:** ~~Loved by 10,000+ happy homeowners~~
> **After:** Project names and photography are placeholders — swap in your own jobs before this goes live.

# Signs of AI writing — the catalogue

Slop is the sound of an unwritten rule. A model asked to "write good copy" writes the
average of everything it has read, and that average has a very recognisable accent.

The canonical source is **Wikipedia's "Signs of AI writing"**, maintained by WikiProject

authorship test or an independently validated naturalness measure. Everything below is organised into five groups, because the fix differs per
group. These five groups are exactly what `../scripts/deslop.py` scores.

## 1 · Vocabulary

`navigate the landscape` · `in today's fast-paced world` · `it's important to note` ·
`it's worth noting` · `that being said` · `at the end of the day` · `unlock` ·
`supercharge` · `elevate` · `game-changing` · `revolutionise` · `harness the power of` ·
`dive deep` · `myriad` · `plethora` · `realm` · `ever-evolving` · `cutting-edge` ·
`transformative` · `paradigm shift` · `synergy` · `holistic` · `embark`

**Tier 2, fine once and damning in every section:**
`leverage` · `foster` · `crucial` · `pivotal` · `streamline` · `empower` · `showcase` ·
`curated` · `meticulous` · `compelling` · `innovative` · `comprehensive` · `journey` ·
`solution` · `effortless` · `intuitive` · `world-class` · `best-in-class` · `unleash` · `boost`

On a marketing site the second tier does more damage than the first, because `streamline
your workflow` is the exact sentence every competitor also shipped.

The fix is a **plainer word, not a synonym**. `leverage` does not become `utilise`.
It becomes `use`.

## 2 · Constructions (the shapes)

Louder than any single word, because they are shapes rather than vocabulary:

| Shape | Example | Fix |
|---|---|---|
| `not just X, but Y` | `It's not just a course, it's a journey` | Cut the first clause, keep the claim |
| `more than just` | `More than just another app` | Same |
| `whether you're X or Y` | `Whether you're a beginner or a pro…` | Name the one reader you mean |
| `that's where X comes in` | `That's where Acme comes in` | State what X does |
| `say goodbye to` | `Say goodbye to guesswork` | Name what replaces it |
| `imagine a…` | `Imagine a world where…` | Show it instead |
| hedged benefit | `helps you to`, `can help you` | Use a precise verb; retain factual uncertainty |
| stacked hedging | `may potentially`, `could possibly` | Remove redundant hedges only; retain required uncertainty |
| self-answering question | `The result? Faster shipping.` | A sentence |

**`It's not just X, it's Y` is the single loudest tell in English right now.** If you
fix one thing, fix that.

Also in this group: the closing summary nobody asked for (`In conclusion…`), process
bleed (`I've analysed your requirements and structured the following…`), bold-lead
bullets on every item, and symmetrical paragraphs — every paragraph three sentences,
every sentence fifteen words. Humans write a nine-word paragraph and then a forty-word one.

## 3 · Punctuation cadence

- Two or more em-dashes inside one sentence. This is a review heuristic; the package makes no independently
  verified numerical claim about writer populations. The clause after a dash must add
  new information, or it is two sentences pretending to be one.
- Semicolons in web copy. Almost always the wrong register.
- A caveat appended to every claim.

## 4 · Rhythm

The rule-of-three reflex: `faster, smarter, and better`. One tricolon is rhetoric.
Three on a page is a machine. Real writers use two items, or four, or one.

## 5 · Invented proof

Numbers, users, testimonials or ratings the product has not earned. The one group with a
real cost attached: it is the single unrecoverable mistake, and the lift it buys is
smaller than the specificity you could have written instead. If the product has not
launched, the copy says so. "Five minutes of real problems, marked the second you answer"
beats any fabricated number, and it has the advantage of being true.

---

## After the tells are gone

Removing tells leaves clean, dead copy. Put a person back in:

- **Use a specific number, name or date when actually supplied and useful.** "Faster" is nothing. "Four minutes
  instead of forty" is a sentence a human wrote because they timed it.
- **Vary sentence length hard.** Land a three-word sentence after a long one. Rhythm is
  the fastest human signal there is.
- **Use a source-supported point when appropriate for the selected voice.** An opinion, a preference, a thing that
  failed. Safety is the texture of AI writing.
- **Use the reader's actual words.** Mine reviews, tickets, comments. Nobody says
  `streamline your workflow` out loud.
- **Keep one rough edge.** A contraction, a fragment, a sentence starting with "And".
  One rough edge is texture. Five is sloppy.

## Purpose
Apply to Vietnamese sample answers, forms, questionnaires, tables and report copy after final assembly. This is a relevance/voice check, not a ban on facts about authorship or a replacement for evidence/privacy review.

## Five checks for every reader unit
1. **Đúng ô:** State the exact question or reader job. Each sentence must answer it or preserve a material limit on its answer. Delete unrelated self-description, submission logistics and future workflow promises.
2. **Đúng vai:** Write a sample in the respondent's voice, not as an agent explaining how to fill a form. Do not add “Mình tự điền hồ sơ này” unless the field genuinely asks who completed the form.
3. **Đủ ý:** Keep specific facts, relevant uncertainty, source limits and permission boundaries. Do not remove “chưa có số liệu” from a performance field just because it is a limitation.
4. **Đúng chỗ:** Put navigation, upload instructions and cross-tab references in guidance or the start page, not sample answers. A sample channel field supplies its channel, representative content and available metrics rather than “sẽ gửi ở tab khác”.
5. **Tự nhiên:** Read only the question plus sample. Would a real respondent plausibly write this? Use one coherent persona; avoid repetitive wrappers such as “Minh họa” or generic “Thương hiệu mẫu A”.

## Examples and exceptions
- Identity: BAD “Mình là Linh... Mình tự điền hồ sơ này.” → GOOD “Mình là Linh, làm kênh Bếp Nhà Linh về bữa tối nhanh.”
- Channel: BAD “Sẽ gửi đường dẫn ở tab Dữ liệu gửi.” → GOOD “TikTok: https://example.com/bep-nha-linh/tiktok. Video tiêu biểu: Cơm gà một chảo. Mình chưa tổng hợp lượt xem.”
- Permission field: “Mình là người duyệt nội dung cuối cùng” is RELEVANT when the question asks for the approver. Do not blacklist “mình”, “duyệt” or first-person wording.
- No proof: “Mình chưa bán sản phẩm nên chưa biết lý do mua thật” is RELEVANT in a buying-objection field; never replace it with invented sales evidence.
- Handoff guide: Cross-tab navigation is RELEVANT in its designated instructions, not in examples.
- A person or creator named in a supplied example is fictional only when the context explicitly says so. Never label real user facts fictional.

## Safe illustration links
Only when fictional examples are requested, use example.com or an explicitly labelled placeholder as plain illustrative text. State once per standalone template that persona, quotations, metrics and example links are fictional. Do not fabricate plausible real accounts, claim links work, browse placeholder links, or put examples in answer fields. A real report CTA or source citation still needs a verified actual destination; illustrative links cannot pass that gate.

## Verification
Inventory all sample-answer fields and sentence dispositions: retain / remove / rewrite with reason. Review neighboring fields for consistent persona, time, offer and capacity. Reopen the destination and check the complete changed copy, line breaks and emphasis. Check semantic counterexamples above; phrase searches only raise review flags and cannot prove semantic quality. Keep author, input provenance and permission records in the internal evidence layer even when their public columns are removed.

| Need | Path | Rule |

Use this reference for reader-facing Vietnamese that feels machine-shaped, over-smoothed, translation-shaped, or mismatched to its professional register. It extends the canonical editor; it does not create another Vietnamese voice owner.

## THREE-LAYER DIAGNOSIS

Read in this order:

1. **Paragraph:** check argument flow, opening/closing function, repeated structure, abstract claims without usable information, and uniform rhythm.
2. **Sentence:** identify actor, action, logic, certainty, condition, and the information that should arrive first in natural Vietnamese.
3. **Word:** only then inspect clichés, nominalization, weak verbs, literal metaphors, filler transitions, and terminology.

When several patterns hit one sentence, repair it once at the structural level and reassess. Do not perform a chain of one-for-one synonym replacements.

## INTERVENTION LEVELS

- **Light:** local repair while preserving structure and voice.
- **Medium:** merge or split sentences, remove empty framing, or clarify the actor.
- **Deep:** reorder a paragraph only when its structure hides the decision or argument; recheck the preservation ledger after every paragraph.

Prefer the lowest level that solves the reader problem. Keep already-natural sentences unchanged.

## REGISTER MAP

- **Technical:** prioritize precision, explicit actors, consistent terms, and unchanged code/API/paths. Passive voice may be correct when the process matters more than the operator.
- **Workplace:** state action, owner, deadline, and handoff directly; preserve the organization's form of address.
- **Academic:** retain hedges, limitations, citations, terminology, and valid nominalization.
- **Marketing/product:** persuasion requires supplied evidence; never invent benefits, metrics, testimonials, or urgency.
- **Customer care:** acknowledge the issue briefly, then state current status and next action; do not promise beyond authority.
- **Social/blog:** preserve authentic colloquial, regional, generational, and rhythmic choices when they belong to the source voice.
- **Administrative/legal/policy:** precision outranks conversational ease; preserve definitions, scope, conditions, obligation words, and legally functional lists.

## TRANSLATIONESE PATTERNS

- Long noun chains, stacked nominalization, dummy subjects, weak verb constructions, English-order passive clauses, literal business metaphors, and multiple administrative layers may justify structural repair.
- `thông qua việc`, passive voice, long sentences, Sino-Vietnamese terms, `tận dụng`, and `liền mạch` are not errors by themselves.
- Preserve near-English order when subtitle timing, bilingual forms, or sentence alignment requires it.
- Do not convert `may` into certainty, `shall` into advice, association into causation, or an approved term into a newly invented Vietnamese term.

## TWO-WAY AUDIT

1. Compare output against input to detect missing facts, numbers, names, dates, negation, conditions, exceptions, certainty, scope, quotations, and terms.
2. Read output alone to detect awkward rhythm, register drift, illogical transitions, unnecessary edits, and terminology inconsistency.

Any invented fact or changed decision truth is a blocker even when the result sounds fluent. When naturalness conflicts with preservation, preserve truth and flag the unresolved wording.

## Cơ chế kiểm tra ba lớp

1. **Tín hiệu từ ngữ và cấu trúc:** bộ lint tìm cụm sáo, trật tự giống tiếng
   Anh, từ tiếng Anh không cần thiết, nhịp liệt kê đều, câu hỏi tự hỏi–tự trả lời,
   mở đầu viết thường và dấu câu dày. Kết quả là cảnh báo có dòng và mẫu cụ thể.
2. **Tín hiệu ở cấp đoạn:** người biên tập xem chủ thể, động từ, quan hệ nguyên
   nhân–kết quả, độ dài câu và sự lặp mở đầu. Cùng một mẫu xuất hiện dày trong
   một trang hoặc một phần đáng xem lại hơn một lần xuất hiện có chủ ý.
3. **Cổng nguồn và người đọc:** mọi số liệu, bằng chứng xã hội, tên riêng, điều
   kiện và mức độ chắc chắn phải khớp nguồn khóa. Đọc thành tiếng và đọc lại sau
   khi ráp dữ liệu để bắt lỗi mà regex không thấy.

hoặc **BLOCKED**:

- **BLOCKED:** sai nghĩa, đổi số liệu/chủ thể/điều kiện, bịa bằng chứng, hoặc
  không thể nối câu với nguồn.
- **WARNING:** câu dịch theo trật tự tiếng Anh, sáo, lặp nhịp, từ tiếng Anh
  không cần thiết, dấu câu máy móc hoặc lỗi ráp chữ; cần người sửa và đọc lại.
- **PASS:** không còn lỗi chặn và mọi thay đổi đã đối chiếu nguồn. PASS không
  chứng minh văn bản do người viết hay đạt “điểm tự nhiên” nào.

## Không thể quyết định bằng lint

Lint không tự biết một câu trang trọng là dụng ý pháp lý, một thuật ngữ là bắt
buộc của giao diện, hay một trích dẫn đang được giữ nguyên. Lint cũng không
đánh giá được hàm ý hình ảnh, giọng của người phát ngôn, mức phù hợp với thương
hiệu hoặc việc một insight có thật sự đổi quyết định. Những điểm này cần người
đọc có ngữ cảnh và bằng chứng nguồn.

### Biên nhận tối thiểu

Mỗi lượt phát hành ghi `status`, danh sách finding theo dòng, nguồn claim đã dùng,
allowlist thuật ngữ, các câu đã sửa và giới hạn còn lại. Không ghi một điểm số
“tự nhiên” thay cho biên nhận.

# Vietnamese lint–rewrite–re-lint gate

| Need | Path | Rule |
|---|---|---|
| Order | [Order](#order) | Read when you need order; retain the prerequisites and limits stated in that section. |

Owner: `viet-natural-decision-editor/v0.2`. This reference adapts the useful
mechanism from SlopMonster without importing its English vocabulary or score.
For the detection catalogue, examples and limits, read [Nhận diện văn tiếng
Việt có dấu hiệu máy móc](vietnamese-ai-sounding-detection.md).

## Order

1. Freeze the final merged reader text and its source claims.
2. Run `scripts/check_vietnamese_release.py`.
3. Classify each finding as a lexical/translation, structure/rhythm,
   source-bound proof, or final-merge signal.
4. Repair only the flagged wording, using the meaning-first workflow and
   preserving numbers, conditions, actors, certainty, names, links, and
   machine values.
5. Run the checker again after the last merge and keep the receipt beside the
   report evidence.

## Statuses

- **BLOCKED:** meaning drift, dropped condition, changed number or actor,
  unsupported proof, or a sentence that cannot be reconciled to its source.
- **WARNING:** translation-shaped order, abstract slogan, mechanical rhythm,
  unnecessary generic English, or lowercase sentence opening.
- **PASS:** no blocker remains and all changed units were checked against
  source truth. PASS is a release status, not a numerical naturalness score.

The checker is deterministic evidence. It does not replace a Vietnamese reader
review, a read-aloud pass, or the the artifact owner source/render gates. Terms owned
by a report template, such as `Input standard` and `Output standard`, may be
passed in the explicit allowlist and must not be translated by this gate.

The catalogue's patterns and counts are review signals only. They do not decide
whether a sentence was written by AI, and they must not rewrite a legal quote,
proper name, technical key, or intentional brand line.

## Source-bound proof

Quantities and social proof require a source-claim list. A number beside
`khách hàng`, `người dùng`, `đánh giá`, `tin tưởng`, `hài lòng`, or a similar
proof noun is BLOCKED when the exact claim is absent from that list. This is a
source check, not a fluency judgment.

## Phạm vi

Tài liệu này bổ sung cách kiểm chứng cho chủ sở hữu tiếng Việt hiện có. Không tạo thêm bộ quyết định giọng. Quy tắc bảo toàn nghĩa và quyền hạn luôn ưu tiên hơn cách nói trôi chảy.

Việc sửa một ví dụ sai nghĩa, tăng kiểm kê câu hoặc kích hoạt bộ kiểm tra cấu trúc có thể được phê duyệt độc lập. Chưa có kết quả người đọc thì chỉ được nói đã sửa cách kiểm tra, không được nói tiếng Việt đã tự nhiên hơn.

## Hồ sơ giọng cho từng báo cáo

Trước khi viết, ghi một hồ sơ ngắn gồm:

- Người đọc và quyết định họ cần đưa ra.
- Vai người nói: Đơn vị tư vấn, người nghiên cứu, người vận hành hoặc người bán hàng.
- Loại tài liệu: Báo cáo đầy đủ, thẻ nội dung, bảng hoặc bài trình bày.
- Xưng hô, độ trực tiếp, mức giải thích thuật ngữ và những điều không được hứa.
- 5–10 câu mẫu do người có thẩm quyền duyệt cho chính giọng này; ghi nguồn và ngày duyệt. Chưa có mẫu thì đánh dấu hồ sơ tạm, không tự gắn nhãn đã duyệt.
- Ngoại lệ cần giữ nguyên: Tên riêng, điều khoản, đơn vị, trích dẫn hoặc câu đã tự nhiên.
- Mã kiểm tra SHA-256 của tệp hồ sơ sau khi chốt; thay hồ sơ thì tạo phép thử mới.

Giọng tư vấn nêu đề xuất rõ nhưng không tự thêm người đề xuất. Giọng nghiên cứu giữ giới hạn bằng chứng. Giọng bán hàng không tự thêm lợi ích, mức khẩn cấp hay số liệu. Không áp cùng giọng vào cả ba.

## Bốn cách xử lý

- `no_change`: Giữ nguyên khi câu đã rõ và đúng vai.
- `rewrite`: Sửa cách diễn đạt, giữ nguyên mọi mệnh đề và giới hạn có ý nghĩa.
- `review_comment`: Nêu vấn đề lập luận hoặc mâu thuẫn; không âm thầm biến kết luận sai thành nguồn đã xác thực.
- `needs_author_decision`: Chưa thể viết bản cuối vì thiếu thông tin ảnh hưởng đến nghĩa. Hỏi đúng chỗ thiếu; không tự điền.

Những cách xử lý này là kỳ vọng của ca thử, không phải đáp án văn phong duy nhất. Người đánh giá có thể phản biện kỳ vọng và ghi lý do trước khi thay phiên bản bộ thử.

## Viết và kiểm nghĩa riêng

Lượt viết dùng hồ sơ giọng và nguồn đã khóa. Lượt kiểm so sánh từng câu với nguồn, dò chủ thể, số liệu, đơn vị, thời gian, phủ định, điều kiện, ngoại lệ, nguyên nhân và mức chắc chắn. Người kiểm ghi đoạn nguồn và đoạn sửa để chứng minh nhận xét. Cờ tự khai giữ nghĩa không thay được đối chiếu.

Lượt kiểm nghĩa có thể do cùng công cụ chạy riêng để tìm lỗi, nhưng không gọi đó là người chấm độc lập. Câu đổi nghĩa không đủ điều kiện thắng dù đọc hay hơn. Từ được bôi đậm hay đổi màu không chứng minh câu tự nhiên.

## Thiết kế phép thử nhỏ

Gói này không chứa bộ ca thử, phiếu điểm hay dữ liệu người đọc. Khi cần
đánh giá thực, người quản lý chuẩn bị ca mới có quyền sử dụng, bỏ dữ liệu riêng
và chốt phần phát triển/phần giữ riêng trước khi sửa hướng dẫn. Số người và số
ca bên dưới là thiết kế ví dụ; không phải chứng nhận chất lượng phổ quát.

1. Chốt hai cách viết, hồ sơ giọng, bộ ca và mã tệp trước khi tạo đầu ra.
2. Dùng 20 ca phát triển để sửa quy tắc. Khi bắt đầu xem kết quả phần giữ riêng, đóng băng hướng dẫn; nếu tiếp tục sửa theo chúng thì đổi bộ giữ riêng.
3. Lưu đủ nguồn, bản A và B. Xáo thứ tự A/B từng ca; giữ tên phương pháp và bảng giải mã ngoài bản đưa người chấm.
4. Mời ít nhất hai người thật đọc tiếng Việt trong bối cảnh báo cáo. Mỗi người chấm đủ 20 ca giữ riêng và không xem câu trả lời của người kia.
5. Trước chấm giọng, mỗi bản nhận kết luận nghĩa: `pass`, `fail` hoặc `undetermined`, có lý do cụ thể. Bản chưa rõ nghĩa không được tính là bản thắng.
6. Chấm độ tự nhiên 1–5, giải thích điểm vướng; chọn `A`, `B`, `tie` hoặc `neither`. Hòa và cả hai chưa đạt là hai kết quả khác nhau.
7. Khóa phiếu riêng, sau đó mới thảo luận chỗ bất đồng. Giữ cả kết quả ban đầu; không xóa ý kiến thiểu số.
8. Báo số ca đủ dữ liệu, lỗi nghĩa, thắng/thua/hòa/cả hai chưa đạt và bất đồng giữa người đọc. Hai người và 20 ca không chứng minh chất lượng trên mọi báo cáo.

Một người nhập dữ liệu có thể chép phiếu đã nhận, nhưng phải ghi nguồn phiếu và người chấm thật; không dùng đầu ra AI để điền vào ô người chấm. Không cần lưu thông tin cá nhân ngoài mã người chấm và dẫn chứng phiếu trong phạm vi được phép.

## Bộ kiểm tra chứng minh gì

Gói này không kèm công cụ kiểm phiếu nghiên cứu. Nếu thực hiện phép thử với
người đọc, giữ nguồn, mã tệp, phiếu riêng và các đối chiếu thực trong dữ liệu
của nhiệm vụ. Kiểm tra đủ hồ sơ không chứng minh đánh giá trung thực hay câu
tự nhiên hơn. Chưa nhận phiếu thật thì không được tự tạo điểm thay người chấm.

Trạng thái còn thiếu phải là `REVIEW_INCOMPLETE`. Không tạo điểm mẫu rồi để người dùng tưởng là kết quả thật.

### Chú thích thuật ngữ

- **SHA-256:** Mã tệp dùng để phát hiện thay đổi.
- **Ca phát triển:** Câu được dùng để xây và sửa quy tắc.
- **Ca giữ riêng:** Câu dành để đánh giá sau khi chốt quy tắc.
- **A/B:** Hai bản viết được ẩn tên cách tạo.

This module defines the reusable profile workflow for Vietnamese reports,
slides, documents, spreadsheets and design copy. The canonical Vietnamese
owner remains Voice’s internal Vietnamese function; this is a capability module, not
a competing language skill.

## 1. Purpose and scope

Own Vietnamese profile extraction and final language review. The shared brand module supplies
cross-language brand voice and situational tone when a system profile exists;
this module remains usable without Design for ordinary Vietnamese editing.
Do not create a second independent brand profile from the same samples.

## 2. Inputs

Use the current reader, purpose, channel, facts, language, approved profile,
permitted samples and existing promotion authority. If a brand voice binding
is supplied, inspect its actual rules and version/hash rather than trusting
its label. Missing or stale rules block that brand-specific claim, not neutral
Vietnamese drafting.

## 3. Workflow

### Entry choice

Reuse an existing task choice and profile before asking. Only for a requested profile operation with no resolved choice, ask: “Bạn muốn dùng giọng văn có sẵn hay tạo giọng văn mới?” Ordinary editing does not require profile creation. For an existing
profile, show its audience, register, sentence rhythm, preferred words, banned
words, technical-term policy and a short example.

For a new profile, collect a 200–500 word sample in the target language. If it
is too short, fragmented or not representative, mark `NEEDS_SAMPLE` and do not
invent a voice.

NEEDS_SAMPLE applies to a learned personal/brand profile. It does not prohibit
a clearly labeled neutral baseline or applying an existing complete profile.
Five pieces are a useful diversity target, not a required second quota.

### Shared brand profile

When a approved brand profile is bound, consume its chosen traits, tone context,
preferred/avoided terms and claim constraints. Preserve the single profile
identity; return proposed Vietnamese adaptations as a scoped delta rather than
silently rewriting the multilingual master. The parent report owner retains
structure, facts and format. Do not translate an English word-count threshold
into a Vietnamese quality gate or introduce a mandatory report recap.

If the request is to research/create a multilingual brand voice, use Voice’s shared brand function. It supplies the research method; this owner
applies Vietnamese realization and the final source-bound language check.
No Design dependency is required for standalone Vietnamese editing with
complete supplied rules.

### Profile extraction

Record observations before recommendations: sentence length and paragraph
rhythm; preferred verbs, nouns, connectors and pronouns; idea order and
transitions; point of view and certainty markers; heading and bullet behavior;
and preferred, tolerated or avoided terms.

Generate four tables when requested: `Rule cá nhân`, `Giọng văn`, `Cấu trúc câu
chuyện`, and `Tối ưu hóa SEO`. Personal rules take precedence over defaults;
record conflicts rather than silently resolving them.

### Evolving a profile

When feedback changes wording, structure or rhythm and promotion authority is not already explicit for that profile, ask: “Bạn có muốn chuyển
phản hồi này thành cập nhật cho framework giọng văn và danh sách từ nên dùng/từ
cần tránh không?” Only an affirmative answer may update the profile. Store the
feedback excerpt, before/after example, reason, date and affected contexts.

The default Vietnamese report voice is direct, concrete and decision oriented:
one idea per line, clear subject and action, natural Vietnamese word order,
short paragraphs, selective emphasis and explicit uncertainty. Preserve
numbers, conditions, actors, source boundaries and certainty. Translate generic
English prose; retain `Input standard`, `Output standard`, `Block A`, `Block B`,
`Block C` and official names when they are field labels or source terms.

Run the Vietnamese lint–rewrite–re-lint gate after final content merge and
before layout/export. Use `PASS`, `WARNING` or `BLOCKED`; never use one
naturalness score. Voice changes cannot change source truth, layout, scene IDs,
strategy or output schema.

## 4. Tools and permissions

Read scoped supplied materials. Do not upload samples, install a source
package, auto-promote feedback, or change shared skill instructions. Ordinary
copy repair does not grant shared profile promotion. Method changes remain
subject to explicit approval and host governance.

## 5. Output

Return the selected profile identity/status, Vietnamese wording or proposed
profile delta, source-linked rules/examples, unresolved context and language
review result. Preserve the parent artifact's schema and machine identifiers.

## Package file: functions/en/scripts/deslop.py

```python
#!/usr/bin/env python3
"""Hunt AI tells in the visible copy of a built page. Regex, no opinions, exits red.

    python3 deslop.py index.html
    python3 deslop.py index.html --view view-site     # score one tab only
    python3 deslop.py --text "some copy to check"

This reads only what a visitor can SEE: it strips <script>, <style>, and every HTML
tag, so it scores the words on the page rather than the markup around them.

Scoring is out of 5. Below 5 exits non-zero. That is deliberate — "mostly clean"
copy is how a page ends up sounding like every other AI page on the internet.
"""
import html as _html   # aliased: `visible_text` takes a parameter named `html`
import re
import sys

# ── the catalogue ────────────────────────────────────────────────────────────
# Grouped by why they are a tell, because the fix differs per group.

# Matched by root, so every inflection fires: `elevate` also catches elevates,
# elevated, elevating, elevation. Landing-page copy is written in the third
# person ("Acme elevates your workflow"), so exact-string matching missed the
# single most common surface form of every word here.
VOCAB = [
    'delve', 'leverage', 'seamless', 'elevate', 'robust', 'unlock', 'unleash',
    'empower', 'streamline', 'cutting-edge', 'state-of-the-art', 'game-changer',
    'game-changing', 'revolutionize', 'revolutionise', 'transformative',
    'transformation', 'innovate', 'holistic', 'synergy', 'synergies', 'paradigm', 'bespoke',
    'meticulous', 'tapestry', 'testament', 'beacon', 'unparalleled', 'supercharge',
    'turbocharge', 'effortless', 'next-level',
    # second tier: fine once in a long page, damning in every section
    'pivotal', 'foster', 'showcase', 'compelling', 'intuitive', 'world-class',
    'best-in-class',
]

# Words with an ordinary literal sense — "we craft furniture", "harness the
# horse", "the landscape of the valley". Matched exactly, never by root, so the
# innocent use survives and only the marketing inflection is caught.
VOCAB_EXACT = [
    'crafted', 'curated', 'harnessing', 'harness the power', 'journey', 'realm', 'landscape',
    'navigate the', 'in the world of', "in today's", 'ever-evolving', 'fast-paced',
    'look no further', 'dive in', "let's dive", 'deep dive', 'embark',
    'unlock the power', 'buckle up', 'the secret sauce', 'level up',
]


def _root_pattern(word):
    """A regex matching `word` and its inflections.

    Strip a trailing e/ed/ing/ly to get the root, then allow the suffixes back.
    The bare `e?` alternative is load-bearing: without it, stripping the `e` from
    `elevate` leaves `elevat`, which no longer matches the base form itself.
    """
    root = re.sub(r'(ed|ing|ly|e)$', '', word)
    if len(root) < 4:                     # too short to stem safely
        return rf"(?<!\w){re.escape(word)}(?!\w)"
    return rf"(?<!\w){re.escape(root)}(?:e|es|ed|ing|ion|ions|ional|ive|al|ally|s|ly|ness)?(?!\w)"

# Negated "just/only/merely/simply", in either register.
#
# `\bnot\b` cannot match inside `isn't` — there is no standalone `not` token there — so
# an uncontracted-only pattern misses every contracted form, which is the register a
# model reaches for when it is trying hardest to sound human. Matching the `n't` suffix
# covers isn't / aren't / wasn't / doesn't / don't / won't / can't without enumerating
# them. Straight and curly apostrophes both.
_NEG_JUST = r"(?:\bnot|n['’]t)\s+(?:just|only|merely|simply)\b"

# The Y clause of the swap, reached across a comma or a single full stop. It is not
# always a copula — "it doesn't just park you, it GETS you there" is the same move — so
# this takes a pronoun subject and lets any verb follow. The punctuation carries the
# precision: "It's not just about money." has no Y clause and stays clean, and so does
# "Do not just take my word for it."
_XY_TAIL = r"[^!?]{0,80}?[,.]\s*(?:it|this|that|they|we|you|he|she|i)\b"

PHRASES = [
    # constructions, not words — these are the loudest tells
    # The contracted and uncontracted forms both matter: formal register is not an
    # adversarial rewrite, it is the default thing a model emits.
    (_NEG_JUST + r"[^.!?]{0,80}\bbut\b", "the 'not just X, but Y' construction"),
    (_NEG_JUST + _XY_TAIL, "the 'not just X, it's Y' construction"),
    (r"\bwhether you(?:'?re| are)\b[^.!?]{0,40}\bor\b", "the 'whether you're X or Y' opener"),
    (r"\bmore than just\b",                        "'more than just'"),
    (r"\b(that|this)(?:'?s| is) where\b[^.!?]{0,30}\bcomes? in\b", "'that's where X comes in'"),
    (r"\bsay goodbye to\b",                        "'say goodbye to'"),
    (r"\bimagine (a|an|the)\b",                    "the 'imagine a…' opener"),
    (r"\bin conclusion\b|\bto sum up\b",           "essay-summary phrasing"),
    (r"\bwhen it comes to\b",                      "'when it comes to' filler"),
    (r"\bat the end of the day\b",                 "'at the end of the day'"),
    (r"\bthe key is\b|\bthe truth is\b",           "throat-clearing opener"),
    (r"\bhelps? you to\b|\bcan help you\b",        "hedged benefit ('helps you to…')"),
    (r"\bmay potentially\b|\bcould potentially\b|\bmight possibly\b", "stacked hedging"),
    (r"\bvery unique\b|\bquite literally\b",       "intensifier padding"),
    # Openers and self-answering questions. Cheap literals, near-zero false
    # positives, and they cover the register a pure vocabulary list cannot see.
    (r"\bhere'?s the thing\b|\blet'?s break (it|this) down\b|\bthe best part\b",
                                                   "throat-clearing opener"),
    (r"\bready to get started\b|\blet'?s get started\b", "boilerplate CTA"),
    (r"\bthe (result|answer|catch|kicker|upshot)\?\s", "self-answering question"),
]

# Invented social proof. Deliberately broad: this is the one mistake with no
# route back, so recall matters more than precision. If your number is real and
# you can evidence it, pass --allow-proof and the rule drops to advisory.
# Hyphenated compound modifiers. One is ordinary English: "a 25-year warranty".
# Four in a sentence is a model reaching for authority it has not earned, and the
# giveaway is that they stack in front of one noun: "our industry-leading,
# context-aware, best-in-class, AI-powered platform". The floor is high on purpose.
# Real trade copy runs one to three per hundred words, and stacked slop runs sixty.
COMPOUND = re.compile(r'\b[a-z]{2,}-[a-z]{2,}(?:-[a-z]{2,})*\b', re.I)
COMPOUND_FLOOR = 4

PROOF = re.compile(
    # Digits, thousands separators and a decimal point, but never a trailing
    # full stop. Absorbing it let "Don't Make Me Think, 2000. The reader…" read
    # as a proof claim, because the year swallowed the sentence break and then
    # reached across it for a noun. A number and its noun live in one sentence.
    r"([\d][\d,]*(?:\.\d+)?)\s*\+?\s*"
    r"((?:happy|early|active|satisfied|verified|trusted|delighted)\s+)?"
    r"(?:\w+\s+){0,1}"
    r"(users?|customers?|learners?|students?|teams?|members?|companies|businesses"
    r"|homeowners?|subscribers?|clients?|patients?|readers?|sites?|projects?)"
    # Closed with a word boundary, like `_root_pattern`. Without it `sites?`
    # matched inside "sitemaps", `teams?` inside "teamsters" and `projects?`
    # inside "projectors", and "12 sitemaps" scored as invented social proof.
    r"(?!\w)",
    re.I)


def normalise(t):
    """Fold the typographic variants back to the plain ones the rules match.

    A non-breaking hyphen is not `-`, \xa0 is not a space, and a curly
    apostrophe is not `'`. Miss any of them and `cutting-edge`,
    `it's not just X` and `whether you're` all stop matching on real copy,
    because real copy is exactly where the pretty characters come from.

    Every input path runs through here. Markdown skipped it once, and the
    construction rules went blind on every .md file with a smart quote in it.
    """
    t = t.replace('‑', '-').replace('\xa0', ' ').replace('’', "'")
    return re.sub(r'\s+', ' ', t).strip()


def visible_text(html):
    """What a visitor actually reads. Script/style stripped, tags removed."""
    t = re.sub(r'<(script|style)\b.*?</\1>', ' ', html, flags=re.S | re.I)
    t = re.sub(r'<!--.*?-->', ' ', t, flags=re.S)
    t = re.sub(r'<[^>]+>', ' ', t)
    # Decode every entity, not a hand-written six. Numeric entities used to leak
    # through as literal text: each `&#x27;` donated a phantom semicolon to the
    # punctuation rule, and every apostrophe-encoded page went blind to the
    # `it's not just X` and `whether you're` patterns.
    t = _html.unescape(t)
    return normalise(t)


def read_utf8(path):
    """Read a file as UTF-8, whatever the machine's locale says.

    open() with no encoding= uses the locale's, which is cp1252 on a stock
    Windows install. A UTF-8 page then decodes its em-dashes and curly
    apostrophes into mojibake, .replace('\u2019', "'") never fires, and
    window.count('\u2014') counts zero. The punctuation and construction rules
    go silently blind: the same copy scores 4/5 through --text and 5/5 CLEAN
    from a file path, and the file path is what CI wires in.

    A gate that passes because it cannot read is worse than no gate at all.
    Reported by @Azrael259 in #3, who hit it on Windows.
    """
    return open(path, encoding='utf-8', errors='replace').read()


def markdown_prose(md):
    """The prose of a Markdown file, with the specimens removed.

    A literal is not copy. A README that documents `delve` has not shipped the
    word, it has quoted it, and a linter that cannot tell the difference makes
    every catalogue score zero. So four things come out before scoring:

      fenced blocks   ```…```      commands and code, never prose
      inline code     `delve`      the specimen being named
      struck text     ~~before~~   the line being shown as wrong, on purpose
      images          ![alt](src)  alt text is metadata, not body copy

    Link text stays, because that is read as part of the sentence. Everything
    else is scored exactly as before: this strips markup, it does not soften a
    single rule.
    """
    md = re.sub(r'```.*?```', ' ', md, flags=re.S)
    md = re.sub(r'!\[[^\]]*\]\([^)]*\)', ' . ', md)
    md = re.sub(r'\[([^\]]*)\]\([^)]*\)', r'\1', md)
    # Stand-ins, not deletions. Removing `[needs number]` outright welds
    # "you do not have, write ... and move on" into a false rule-of-three, and
    # a linter that invents a hit is worse than one that misses. Two letters
    # keep the clause intact without ever matching a rule itself.
    md = re.sub(r'`[^`]*`', ' it ', md)
    md = re.sub(r'~~.*?~~', ' it ', md, flags=re.S)
    # Headings, table cells and rows are separate copy, not one long sentence.
    # Joined, two em-dashes from two table rows read as one machine cadence.
    md = re.sub(r'^\s{0,3}#{1,6}\s*(.*)$', r' . \1 . ', md, flags=re.M)
    md = re.sub(r'\|', ' . ', md)
    # A bullet is its own line of copy. Left joined, two list items donate one
    # em-dash each and read as a single machine cadence that nobody wrote.
    md = re.sub(r'^\s*(?:[-*+]|\d+\.)\s+', ' . ', md, flags=re.M)
    md = re.sub(r'^\s*>\s?', ' . ', md, flags=re.M)
    md = re.sub(r'[*_>]', ' ', md)
    return normalise(md)


def audit(text):
    hits = {'vocab': [], 'phrases': [], 'punctuation': [], 'rhythm': [], 'proof': []}
    low = text.lower()

    for w in VOCAB:
        n = len(re.findall(_root_pattern(w), low))
        if n:
            hits['vocab'].append((w, n))

    for w in VOCAB_EXACT:
        n = len(re.findall(rf"(?<!\w){re.escape(w)}(?!\w)", low))
        if n:
            hits['vocab'].append((w, n))

    for pat, label in PHRASES:
        found = re.findall(pat, low)
        if found:
            hits['phrases'].append((label, len(found)))

    # Em-dash density: two or more in one sentence reads as machine cadence.
    # Bounded to a 220-char window on purpose — UI strings (nav items, quiz options,
    # labels) carry no terminal punctuation, so a naive sentence split merges the
    # whole page into one "sentence" and this rule fires on every page. Ask me how
    # I know. A linter that cries wolf gets switched off.
    for s in re.split(r'(?<=[.!?])\s+', text):
        for i in range(0, max(1, len(s)), 220):
            window = s[i:i + 220]
            if window.count('—') >= 2:
                hits['punctuation'].append(('two or more em-dashes in one sentence',
                                            window[:70].strip()))
                break
    for s in re.split(r'(?<=[.!?])\s+', text):
        for i in range(0, max(1, len(s)), 220):
            window = s[i:i + 220]
            found = COMPOUND.findall(window)
            if len(found) >= COMPOUND_FLOOR:
                hits['punctuation'].append((f'{len(found)} hyphenated compounds stacked '
                                            'in one sentence', ', '.join(found[:4])))
                break

    # Floor of 3: two semicolons in a long technical page is a style, not a tell.
    if text.count(';') > max(3, len(text) // 1200):
        hits['punctuation'].append(('semicolon-heavy for web copy', f"{text.count(';')} found"))

    # Tricolon: the rule-of-three reflex. Two shapes, deliberately narrow.
    #
    # With the Oxford comma, three single words: "faster, smarter, and better".
    # Without it, the third item must be a 2–3 word phrase that ends the clause:
    # "Trusted, reliable and built to last". That phrase requirement is what
    # separates a rhetorical flourish from a plain list of services —
    # "Inspection, repair and replacement for homes and commercial buildings"
    # is three real things a roofer does, its third item runs long, and
    # flagging it would be exactly the wolf-crying that gets a linter switched
    # off. Note the shape is what is judged, not the meaning: a three-word
    # closing item ("replacement for homes") does fire, by design.
    for pat in (r'\b(\w{4,}),\s+(\w{4,}),\s+and\s+(\w{4,})\b',
                r'\b(\w{4,}),\s+(\w{4,})\s+and\s+((?:\w+\s+){1,2}\w+)\s*[.!?,;:]'):
        for m in re.finditer(pat, text):
            hits['rhythm'].append(('rule-of-three list', m.group(0)[:60]))

    for m in PROOF.finditer(text):
        hits['proof'].append(m.group(0).strip())

    return hits


def report(hits, label='', allow_proof=False):
    weights = {'vocab': 1, 'phrases': 1, 'punctuation': 1, 'rhythm': 1, 'proof': 1}
    if allow_proof:
        # The one rule a regex cannot judge: it sees a number beside a noun, not
        # whether you can evidence it. --allow-proof still prints the hits, but
        # stops a true, defensible claim from blocking a green build forever.
        weights['proof'] = 0
    failed = [k for k, v in hits.items() if v]
    score = 5 - sum(weights[k] for k in failed)
    score = max(0, score)

    titles = {
        'vocab': 'AI vocabulary',
        'phrases': 'AI constructions',
        'punctuation': 'punctuation cadence',
        'rhythm': 'rule-of-three rhythm',
        'proof': 'possible invented proof',
    }

    if label:
        print(f'── {label}')
    for k in ('proof', 'phrases', 'vocab', 'punctuation', 'rhythm'):
        if not hits[k]:
            continue
        print(f'  {titles[k]}:')
        for item in hits[k][:8]:
            print(f'    · {item[0] if isinstance(item, tuple) else item}'
                  + (f'  ({item[1]})' if isinstance(item, tuple) and len(item) > 1 else ''))
        if len(hits[k]) > 8:
            print(f'    · …and {len(hits[k]) - 8} more')
```

```python
    raw = (root / "VOICE.md").read_bytes()
    need(sha(raw) == v["sha256"], "voice hash mismatch")
    return {"language": language, "voice": v, "guideline": raw.decode("utf-8"),
            "scope": "apply-only; no profile update"}

def changed_paths(before, after, prefix=""):
    if type(before) is not type(after):
        return [prefix]
    if isinstance(before, dict):
        result = []
        for k in sorted(set(before) | set(after)):
            p = prefix + "/" + k
            if k not in before or k not in after:
                result.append(p)
            else:
                result += changed_paths(before[k], after[k], p)
        return result
    return [] if before == after else [prefix]

# Portable snapshot: VoiceBinding.json is optional and host-neutral.
if __name__ == "__main__":
    p = argparse.ArgumentParser()
    p.add_argument("--model", type=Path, required=True)
    p.add_argument("--output", type=Path)
    a = p.parse_args()
    v = json.loads(a.model.read_text(encoding="utf-8"))
    result = compile_voice(v)
    if a.output:
        need(not a.output.exists(), "output exists; choose new version")
        need(".codex" not in a.output.resolve().parts, "no active instruction output")
        a.output.parent.mkdir(parents=True, exist_ok=True)
        a.output.write_text(result, encoding="utf-8", newline="\n")
    print(json.dumps({"status": "PASS", "scope": "field coverage only",
                      "voiceId": v["id"], "languages": sorted(v["locales"])}))
```
